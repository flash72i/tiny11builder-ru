## Вариант 2. Средний (4pda, Reddit r/tiny11, ответ в issue)

**Tiny11 Builder WinUI 0.1.2 — полная русская локализация (интерфейс + исходники)**

Если вы собирали «облегчённую» Windows 11 утилитой Tiny11 Builder от ntdevlabs,
теперь есть полностью русская версия WinUI-редакции 0.1.2.

**Что переведено**
- Всё окно программы: приветствие, выбор образа, список компонентов (≈1000 строк кода
  и 147 XAML-строк), настройки сборки, проверка, создание образа.
- Статусы этапов и журнал сборки, диалоги и сообщения об ошибках.
- Установщик .exe (NSIS) — тоже с русским интерфейсом.
- Юнит-тесты переведены синхронно с кодом: проходят/падают так же, как английские.

**Что НЕ переведено (осознанно)**
- Состояния и имена пакетов DISM, имена служб и ключей реестра, regex-паттерны —
  их читает Windows, перевод сломал бы сборку.

**Как проверено**
- Побайтовые SHA оригинальных файлов апстрима сверены до и после правок.
- Дифференциальные тесты A/B/C: английская сборка, русская сборка, русская+оверлей —
  все различия сводятся только к текстовым артефактам.
- Проверка маршрутизации логики: имена этапов, по которым программа принимает решения,
  согласованы во всех сборках (20/20 probe-проверок).

**Где взять**
- Релиз «Tiny11 Builder 0.1.2_Rus» (zip x64 + Setup.exe, SHA256 в описании):
  https://github.com/flash72i/tiny11builder-ru/releases/tag/v0.1.2_Rus
- Репозиторий с исходниками и отчётом REPORT_RU.md:
  https://github.com/flash72i/tiny11builder-ru

Оригинал: ntdevlabs/tiny11builder, tag winui-v0.1.2. Локализация выполнена с помощью
ИИ (Qwen); логика программы не изменялась.

## Вариант 3. Заметка для Habr / Pikabu (каркас, 5–7 минут чтения)

Заголовок: «Как полностью перевести WinUI-приложение, не трогая его логику: русификация
Tiny11 Builder 0.1.2»

Каркас статьи:
1. **Зачем.** Tiny11 Builder — утилита, которой делают «облегчённые» ISO Windows 11;
   русской WinUI-версии не было.
2. **Что внутри WinUI-сборки.** Строки живут в трёх местах: IL-литералы `#US` в
   `Tiny11Builder.dll` / `Tiny11Builder.Core.dll`, XAML-литералы в бинарном
   `MainWindow.xbf` внутри `Tiny11Builder.pri` (формат MRT `mrm_pri2`), и никаких
   `.resw` — классический ResourceLoader не применить.
3. **Главная ловушка.** Часть строк — не текст, а ключи логики: по именам этапов
   (`Phase`/`Range`) и категориям ComboBox программа принимает решения. Roslyn
   компилирует `switch` по строкам в деревья сравнений по длине и символам, поэтому
   наивная замена литералов ломает маршрутизацию. Решение: сохранить английские
   литералы в таких методах и добавить маленький нормализатор RU→EN на входе.
4. **Вторая ловушка — кодировки.** DISM пишет в консоль OEM (CP866), а .NET без
   `StandardOutputEncoding` читает ANSI (CP1251) — отсюда «иероглифы» в списке редакций.
   В 0.1.2 апстрим починил это сам; наш оверлей умеет это обнаружить и не вмешиваться.
5. **Рантайм-оверлей вместо пересборки XAML.** `Tiny11Builder.Ru.dll` обходит дерево
   визуальных элементов после `InitializeComponent()` и подменяет тексты из XAML
   (147 пар), ведёт журнал `ru-localization.log`, чинит кодировочный мусор и ставит
   иконку-триколор.
6. **Как проверено.** SHA-сверка оригиналов, probe-проверки логики (20/20),
   дифференциальные тесты A/B/C (336 проверок), bind-тест запуска процесса.
7. **Результат и ссылки.** Релиз, исходники, отчёт; что переведено, что оставлено
   английским и почему.
